# SentinelAI v1.0 — readiness report

> **SUPERSEDED on 2026-09-24 by `v1.0-release-report.md`.** Kept as the record of what was true on 2026-09-20. Since then
> Docker Compose, container scanning, Kubernetes/Helm, Terraform (on kind), CI (under `act`), browser E2E, SDK streaming,
> user/team management and per-organization provider credentials have all been implemented or verified. Where this
> document says those are "BLOCKED", "never executed" or "not implemented", it is out of date. Real Gemini/OpenAI/Anthropic
> calls are still BLOCKED.

Prepared **2026-09-20** on Windows 11 / Node 24.21 / Python 3.13 / WSL2 (Ubuntu 26.04).

> **Read this first.** SentinelAI is **not certified production-ready**. Core security behaviour is verified against real
> PostgreSQL, real Redis, a real AI provider, a real antivirus daemon and a real OCR engine. Container orchestration, three
> of four providers, and CI on a runner are **unverified and blocked** on dependencies this machine does not have. Every
> such gap is named below rather than smoothed over.

## 1. Product

SentinelAI is a security gateway between corporate applications and AI models. Every request passes authentication,
authorization and tenant resolution, validation, detection (PII, financial, secrets, credentials, prompt injection,
confidential data), risk scoring and policy evaluation, producing ALLOW / MASK / REDACT / TOKENIZE / HASH / BLOCK. Only
sanitized content reaches a provider. The reply is scanned again before the caller sees it. Everything is audited without
storing the sensitive text itself.

## 2. Architecture

See `docs/architecture/diagrams-v1.md` for architecture, security-flow and deployment diagrams. Services: `apps/api`
(TypeScript gateway), `services/security-engine` (Python detection/policy/risk), `services/token-vault` (Python, Redis),
`services/document-scanner` (Python), `services/ai-router` (TypeScript adapters), `apps/dashboard` (Next.js + BFF), plus
two SDKs. State: PostgreSQL with row-level security per tenant, Redis for the token vault.

## 3. Implemented features

Authentication (API keys, JWT, rotating refresh tokens with reuse detection) · RBAC (5 roles, escalation guard) ·
multi-tenancy with RLS · detection across six categories · policy engine with a never-ALLOW floor · risk engine ·
sanitization including reversible tokenization · output security · four provider adapters · SSE streaming with output
hold-back · document scanning with malware/OCR · zero-knowledge audit trail · usage metrics · dashboard (overview, events,
threats, file scan, policies, usage, API keys, settings) · JS and Python SDKs.

## 10. Tenant isolation

On real PostgreSQL: every table carrying `organization_id` has RLS enabled with a tenant policy; the app role sees only its
own rows; pre-tenant lookups are `SECURITY DEFINER` and not callable by PUBLIC; one organization cannot read, list or revoke
another's API keys; a vault session derived for one caller cannot be hydrated by another, even with the same `session_id`.

## 12. Known limitations

1. **Docker, Kubernetes, Helm, Terraform and CI have never executed.** Treat those files as drafts.
2. **Three of four providers have never been called for real.**
3. **Streaming look-ahead is finite** (`STREAM_HOLDBACK_CHARS`, default 256). A sensitive value longer than the window that
   only becomes detectable at its very end could have its beginning released. `mode: "buffered"` removes this, at the cost
   of latency. Released text cannot be recalled.
4. **The evaluation dataset is self-authored**, so "100%" measures no regression on known cases only.
5. **No NER and no ML classifier**: personal names are not detected; paraphrased injection can evade rules.
6. **EICAR only matches a whole file** (measured against ClamAV 1.5.3), so it cannot simulate malware embedded in a document.
   The development `EicarScanner` substring-matches and is therefore *more* aggressive than real ClamAV.
7. **The dashboard has never been opened in a browser**; layout, accessibility and `EventSource` are unverified.
8. **SDKs do not expose streaming**, and the Python SDK is synchronous only.
9. **No user/team management, no per-organization provider credentials, and seven dashboard pages are unbuilt.**
10. **Rate limiting is per gateway instance**; policy writes and their audit entry are separate transactions.
11. **Access tokens cannot be revoked before expiry** (≤15 minutes).
12. **A PDF scan costs ~3 s** (child-process spawn plus parser import).

## 13. Known risks

| Risk | Mitigation today |
|---|---|
| Anyone holding the vault master keys *and* Redis access can decrypt live sessions | Keys belong in a secret manager, not beside Redis; sessions expire absolutely at 3600 s |
| Compose disables Redis persistence; a persisted Redis would write encrypted values to disk | Keep persistence off, or encrypt the volume |
| A compromised document scanner or vault could lie to the gateway | Internal tokens; the gateway verifies returned hash/size; mTLS is not implemented |
| Provider base URLs are operator config; per-org URLs would be an SSRF surface | Per-org provider URLs are deliberately not implemented in v1.0 |
| WSL-hosted Postgres/Redis are a development convenience | Not a deployment topology; use managed services or containers |

## 14. Required production configuration

Production refuses to start without these (each service validates its own):

- `API_KEY_HASH_PEPPER` (≥32 chars, not a placeholder) and `JWT_ACCESS_SECRET` (≥32 chars, different from the pepper)
- `DATABASE_URL` pointing at a server where the app connects as the **restricted** `sentinel_app` role, not the owner
- `SECURITY_ENGINE_TOKEN`, `DOCUMENT_SCANNER_TOKEN`, `VAULT_TOKEN` (≥16 chars each)
- `VAULT_MASTER_KEYS` (`id:base64`, ≥32 bytes per key) from a secret manager; keep the previous key for one TTL after rotation
- `MALWARE_SCANNER=clamd` with a reachable clamd, and Tesseract installed, or images are blocked
- `SENTINEL_ENV=production`, explicit `API_CORS_ORIGINS` (no wildcard), `SIGNUP_ENABLED=false` unless self-service is wanted
- Review `STREAM_HOLDBACK_CHARS` and `VAULT_TTL_SECONDS` against your own risk and retention policy

## 15. Deployment instructions

Local, no Docker (what was verified here):

```bash
wsl -u root -- bash scripts/development/wsl-infra.sh start     # real PostgreSQL + Redis
wsl -u root -- bash scripts/development/wsl-infra.sh clamav    # real ClamAV (standalone, TCP 3310)
DATABASE_URL=postgresql://sentinel:...@<wsl-ip>:5432/sentinel node scripts/database/migrate-pg.mjs
node scripts/development/dev-stack.mjs                          # engine + scanner + vault + gateway + dashboard
```

Container path (**unverified**): `docker compose up --build`. Do not treat it as working until it has been run.
