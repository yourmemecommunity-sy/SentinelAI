# SentinelAI v1.0 — acceptance checklist

Updated **2026-09-26** from the final regression. A box is ticked only when the thing itself was executed here, against the
real dependency named. Evidence for every line: `v1.0-release-report.md`.

## Functional
- [x] Full pipeline: auth → authorization/tenant → validation → security engine → risk → policy → action → AI router → output security → audit → dashboard
- [x] PII, financial, secret, credential, prompt-injection and confidential-data detection
- [x] ALLOW / MASK / REDACT / TOKENIZE / HASH / BLOCK, with credentials and cards never ALLOWable (engine, gateway and a DB CHECK)
- [x] Reversible tokenization (token vault) with per-session, per-tenant keys
- [x] File scanning: type validation → malware (real ClamAV) → extraction/OCR (real Tesseract) → scan → policy
- [x] Streaming (SSE) with output hold-back — real model, through containers
- [x] JavaScript and Python SDKs, **including streaming, verified against the real gateway and a real model**
- [x] User, invitation and team management (API + dashboard pages)
- [x] Per-organization provider credentials, encrypted at rest, with per-organization routing
- [ ] Dashboard pages: models, applications, audit logs, security evaluation — **NOT IMPLEMENTED** (future roadmap)

## Security
- [x] Critical evaluation suite: **PASS** (PII 140/140, prompt injection 70/70, secrets 108/108, output leakage 26/26)
- [x] Fail-closed on engine, vault, scanner, ClamAV, policy, audit and database failure — proven by stopping each one, and again under load with hangs, SIGKILLs and a network partition
- [x] Zero-knowledge audit: no prompt, reply, file or secret text in any table (real PostgreSQL)
- [x] Cross-tenant isolation (RLS) on real PostgreSQL, in containers and on Kubernetes
- [x] Dependency audits clean (pnpm, pip-audit ×3 services in CI)
- [x] Container image scanning: 0 fixable HIGH/CRITICAL in all 6 images (unfixed Debian base CVEs documented as accepted risk)
- [x] Secret scanning: gitleaks with default rules and **no allow-list** — 0 findings on the exact commit file set; no real credentials; no tracked `.env`
- [x] API fuzzing (995 requests) and rate limits verified on the running stack
- [x] Container hardening asserted on running containers; Redis authenticated; NetworkPolicies enforced on a real cluster
- [ ] Independent external red-team datasets — the evaluation set is self-authored

## Failure safety
- [x] Security engine killed, frozen, or partitioned → requests blocked; provider never called
- [x] Token vault killed → requests that need it blocked (`vault_unavailable`), 10/10 under load
- [x] Token vault under a burst above the connection-pool size → requests queue, not fail (fixed at this stage)
- [x] Document scanner / ClamAV stopped → uploads blocked, never passed unscanned
- [x] Postgres restarted → `503 auth_unavailable`, promptly (no hang), no content released
- [x] Gateway SIGKILLed under load → recovered automatically; no request ever leaked
- [x] Client disconnect mid-stream → upstream aborted, partial output still audited
