# Evaluation Methodology

Runner: `scripts/security/run_evaluation.py` - drives every dataset record through the real `ScanPipeline`.

## Gate (CI fails if any is false)
1. **Critical cases: 100% pass.** A case passes only if the decision equals `expected_action`, every expected entity is detected with an overlapping span, and the pipeline did not fail closed.
2. **False-positive rate on benign controls <= 2%.**
3. **Dataset integrity**: schema valid, ids unique, `source` is `synthetic` or `licensed:<name>`, offsets in range, and each file's SHA-256 matches `datasets/manifest.json` (datasets cannot change without regeneration + review).

## Metrics reported
Per-category pass counts; overall detection rate/recall, precision, false-negative rate, false-positive rate (binary "should be sanitized/blocked"), policy accuracy (decision == expected), latency p50/p95/max/mean.

## Threats to validity (read before trusting the numbers)
- The dataset is **generated by the same team that wrote the detectors**; 100% means "no known case regresses", not "unseen attacks are caught".
- 50 benign controls is a small sample; the FP rate has wide error bars.
- The baseline policy is used; org-specific policies need their own cases.
- Phase 3 adds independent red-team cases and properly licensed public datasets, and tracks recall on a **held-out** set never used for tuning.

## Adding a case
Add the template to `scripts/dataset/generate_synthetic_datasets.py`, re-run it (deterministic, seeded), review the diff, run the gate. A case for every production miss is mandatory ([incident response](../security/incident-response.md)).
